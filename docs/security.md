# Security contract

Ordinary identities are default PocketBase `users`, verified and enabled. Workspace JIT is validated using server-obtained Google claims; direct signup and ordinary identity management are locked. Account deletion is blocked, and disabled/verification changes rotate tokens. Old disabled tokens cannot access REST, SQL, schema, refresh or record realtime. Authority does not derive from notification content.

All business REST lists/views and record realtime are locked. Schema and read-only SQL are the supported application read path. Filtered snapshots expose notification bodies/references only to their sender and recipients. Recipient states/preferences and recipient-action audit events are separately filtered. Senders see recipient responses; one recipient cannot enumerate fellow recipients or their responses. Public-to-colleagues directory/status are intentionally shared. Auth records, hidden submission payloads, SQL metadata/system tables and extensions are not exported.

Writes use REST with application-owned transactional validation. Server attribution, timestamps, recipient/reference creation and publication history are not client-controlled. Publication, its recipients, references and initial event commit together. Unique sender/submission key and canonical payload comparison prevent duplicate retries. Recipient updates and personal settings use expected_revision, with idempotent already-satisfied recipient actions. Batch API is disabled; client bulk operations report each separate outcome and are not atomic as a group.

Notification content and references are immutable. Withdrawal retains content/history; archival belongs to each recipient. Acknowledgement is a deliberate action and does not imply work completion. No action follows merely from fetched Markdown, a reference URL or a status message. Summaries and background polling are read-only.

The browser renders sanitized Markdown and does not load remote embedded images. External references remain independently authorized by their source applications. Browser bearer tokens remain in memory; the portable client caches only application tokens in private per-app/server/user files. No bearer tokens or message content enter desktop notification payloads or cross-tab deduplication storage. Desktop notifications require an open authenticated client; they are best-effort attention signals, not evidence of human receipt.

Operators with direct database or backup access are trusted maintenance identities. There is no promise of end-to-end encryption from operators. Backups contain private application data and authentication settings, so the replica must be dedicated and private. Retention is indefinite pending deliberate maintenance erasure; soft withdrawal/archive are not erasure.
